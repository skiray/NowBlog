## 1. 产品概述

### 1.1 一句话定位

> 一本账，全家用 —— 面向家庭、情侣、室友的多人共享账本 App。

### 1.2 背景与问题

市面主流记账工具（随手记、鲨鱼记账等）以**单用户记账**为核心，多人场景下用户只能：

1. 各记各的，月底对不上账 ——「这个月到底花了多少」永远说不清
2. 用 Excel/微信群记账，汇总靠人肉，体验割裂
3. 借助 AA 类工具（如 Splitwise 类产品），但它们只管「分摊」不管「记账」，无法沉淀完整消费记录

**核心洞察**：多人记账的痛点不在「记账」本身，而在「共享」—— 记的人不需要汇总，看的人实时可见。

### 1.3 产品目标

| 目标 | 衡量指标（上线后 3 个月） |
|---|---|
| 验证多人共享记账的真实需求 | 周活跃账本中 ≥ 40% 有 2 人以上记账行为 |
| 让记账成为低摩擦的日常动作 | 核心用户人均每日记账 ≥ 1.5 笔，「记一笔」耗时 ≤ 5 秒 |
| 建立信任基础 | 次月留存 ≥ 25%（记账工具行业基准线以上） |

### 1.4 目标用户与画像

| 画像 | 场景 | 关键诉求 |
|---|---|---|
| **家庭 CFO**（30-45 岁，管理全家开销） | 超市、房贷、教育支出记在一本账 | 老公/老婆随手记的账我能看到；月底一键看全家开销 |
| **同居情侣**（22-30 岁） | 共同消费多：外卖、约会、房租 | 各自记账自动汇总；谁付的钱谁记，不用对账 |
| **合租室友**（20-28 岁） | 房租水电、公共物品分摊 | 记账 + 简单分摊；账目透明不伤感情 |

**MVP 主画像**：家庭 CFO + 同居情侣（付费意愿与留存最优）。室友分摊场景因涉及 AA 结算复杂度高，MVP 仅覆盖「公共支出记录透明」，不做结算功能。

## 2. MVP 功能范围

### 2.1 优先级定义

- **P0**：MVP 必须交付，缺失则产品不成立
- **P1**：MVP 应交付，时间不够可降级到上线后一个月内的迭代
- **P2**：明确不做，进入需求池排期到 V1.1+

### 2.2 功能清单

#### A. 账户与认证

| 功能 | 优先级 | 说明 |
|---|---|---|
| 手机号 + 短信验证码注册/登录 | P0 | 唯一登录方式；验证码 60s 冷却；支持一键登录（P2） |
| JWT 会话管理 | P0 | accessToken（2h）+ refreshToken（30d），静默续期 |
| 退出登录 / 注销账号 | P0 | 注销需满足合规要求（数据删除流程） |

#### B. 账本与成员（核心差异化）

| 功能 | 优先级 | 说明 |
|---|---|---|
| 创建账本 | P0 | 名称 + 封面色；一个用户可建多本账本 |
| 邀请成员 | P0 | 生成 6 位邀请码（24h 有效）；扫码邀请（P1）；邀请链接 + H5 落地页（V1.1 需求池） |
| 成员角色 | P0 | owner：修改账本名/封面、移除成员、解散、转让；member：记账、查看、邀请成员、设置预算（无管理权） |
| 移除成员 / 主动退出 / 转让 owner | P0 | 被移除成员的既有账目保留（归属标记为「前成员」） |
| 成员列表与活跃度 | P1 | 显示各成员本月记账笔数，激励共同记账 |

#### C. 记账核心

| 功能 | 优先级 | 说明 |
|---|---|---|
| 记一笔：支出/收入/转账 | P0 | 金额（自定义数字键盘）、分类、日期（默认当天，可回溯 7 天）、备注 |
| 记账人标记 | P0 | 每笔账目记录「谁记的」和「为谁花的」（默认记账人自己） |
| 二级分类 | P0 | 内置 20 个一级分类（餐饮/交通/购物…）+ 二级分类；账本内可自定义（P1） |
| 修改 / 删除账目 | P0 | 仅记账人和 owner 可操作，**需在线**（MVP 离线仅支持记新账）；删除进入软删除，保留 30 天可恢复（恢复功能 P2，数据先留） |
| 账目列表 | P0 | 按日分组、显示当日记账人头像；下拉刷新；分页加载 |
| 筛选 | P1 | 按成员/分类/收支类型/时间范围筛选 |

#### D. 统计报表

| 功能 | 优先级 | 说明 |
|---|---|---|
| 月度总览 | P0 | 本月收入/支出/结余，对比上月增减 |
| 分类占比 | P0 | 饼图 + 分类金额排行（全账本维度） |
| 成员贡献 | P0 | 条形图：各成员支出金额与笔数 |
| 趋势折线 | P1 | 近 6 月支出趋势 |
| 周/年维度切换 | P2 | |

> 统计口径：收支统计（月度总览/分类占比/成员贡献/趋势）与预算进度均只计入支出（type=1）；转账（type=3）不计入收支统计与预算，仅在流水中展示。

#### E. 预算

| 功能 | 优先级 | 说明 |
|---|---|---|
| 账本月度总预算 | P0 | owner/member 均可设置；超支 80% 与 100% 时应用内提醒（消息中心 + 在线 WS 推送，当日去重；MVP 不接系统级推送） |
| 分类预算 | P2 | |
| 预算进度条 | P0 | 首页/统计页常驻显示 |

#### F. 体验与基础设施

| 功能 | 优先级 | 说明 |
|---|---|---|
| 离线记账 | P0 | 断网可记新账（MVP 离线不支持编辑/删除），联网后自动同步；同步状态可视化（已同步/同步中/失败重试） |
| 实时同步 | P0 | 其他成员记账后 ≤ 3s 内可见（WebSocket） |
| 记账快捷入口 | P1 | 首页悬浮按钮 + 通知栏快捷方式（Android） |
| 数据导出 | P2 | Excel/CSV 导出（V1.1） |
| 深色模式 | P2 | |
| 多语言 | 不做 | MVP 仅简体中文 |

### 2.3 明确不做（V1.0）

- ❌ 账单自动导入（支付宝/微信）、自动记账 —— 合规与通道风险，V1.1+ 评估
- ❌ AA 分摊结算、还款记账 ——「转账」类型已覆盖简单场景
- ❌ 周期账/自动重复记账
- ❌ 资产账户管理（银行卡/信用卡余额）
- ❌ 社交功能（动态、点赞）
- ❌ 记账提醒推送（P1.5，视工期）

## 3. 核心用户旅程

### 3.1 冷启动（新用户）

```
打开 App → 手机号+验证码注册 → 引导页（3 屏：共享账本/快速记账/实时统计）
→ [路径 A] 创建第一本账本（命名，如「我们的家」）→ 记第一笔账 → 引导邀请成员
→ [路径 B] 输入邀请码加入他人账本 → 直接进入账本首页
```

**转化关键点**：注册 → 记第一笔 ≤ 60 秒；新建账本 → 发出第一个邀请的转化率 ≥ 60%。

### 3.2 日常记账（活跃用户）

```
打开 App（首页=账本流水）→ 点悬浮「+」→ 自定义键盘输金额 → 选分类（默认上次）
→ [可选] 改日期/加备注/标记为谁花的 → 完成 → 3s 内全员可见
```

**体验红线**：常用路径（金额→分类→完成）≤ 5 秒、≤ 3 次点击。

### 3.3 月度复盘（家庭 CFO）

```
统计页 → 本月总览（支出/收入/结余、预算进度）→ 分类饼图（哪类花超了）
→ 成员贡献（谁花的多、谁记的勤）→ 针对性沟通
```

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 「记一笔」页面首屏 ≤ 1s（低端安卓机）；账目列表滚动不卡顿（500+ 条）；接口 P95 ≤ 500ms |
| 可用性 | 服务可用性目标 99.5%；数据零丢失（同步失败本地不删） |
| 安全 | HTTPS 全链路；账本数据严格按成员鉴权（防越权）；不收集银行卡明文信息 |
| 合规 | 《隐私政策》明示数据收集范围；支持账号注销与数据删除（应用商店强制要求） |
| 兼容 | iOS 13+；Android 7.0+；覆盖 TOP 20 机型 |

## 6. 依赖与约束

- **短信通道**：需采购短信服务商（阿里云/腾讯云短信），签名与模板需提前报备（约 1-3 个工作日）
- **应用商店**：iOS 开发者账号（审核 1-3 天/次）；国内安卓市场需软著（加急约 2 周，普通约 1-2 月）——**第 13 周前必须启动**
- **法律**：隐私政策文本 + 用户协议（可用模板起步，建议上线前法律顾问过一遍）
